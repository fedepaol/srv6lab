# Implementation Plan: L2 EVPN VXLAN Overlay

**Branch**: `003-l2-evpn-overlay` | **Date**: 2026-04-23 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/002-l2-evpn-overlay/spec.md`

## Summary

Add L2 EVPN VXLAN overlay between PE1, PE2, PE3. Each PE gets a bridge (br10) in VRF red with VXLAN interface (vni110). TOR route reflector extended with l2vpn evpn address family. Bridge port IPs (192.168.10.0/24) advertised in SRv6 VRF via `network` statement for RemotePE reachability. Setup includes seed pings for neighbor table population.

## Implementation Details

### 1. New template: `templates/l2evpn-setup.sh.tpl`

Bridge + VXLAN setup, appended to PE1/PE2/PE3 setup.sh only:

```bash
# L2 EVPN VXLAN overlay
ip link add br10 type bridge
ip link set br10 master red
ip link set br10 addr ${BRIDGE_MAC}
ip addr add ${BRIDGE_PORT_IP} dev br10

ip link add vni110 type vxlan local ${VTEP_V4} dstport 4789 id 110 nolearning
ip link set vni110 master br10 addrgenmode none
ip link set vni110 type bridge_slave neigh_suppress on learning off
ip link set vni110 up
ip link set br10 up
```

Variables per PE:
| PE  | VTEP_V4  | BRIDGE_PORT_IP     | BRIDGE_MAC         |
|-----|----------|--------------------|--------------------|
| PE1 | 10.0.0.1 | 192.168.10.1/24    | aa:bb:cc:00:00:01  |
| PE2 | 10.0.0.2 | 192.168.10.2/24    | aa:bb:cc:00:00:02  |
| PE3 | 10.0.0.3 | 192.168.10.3/24    | aa:bb:cc:00:00:03  |

### 2. Modified template: `templates/pe-frr.conf.tpl`

Add to global BGP (after ipv6 vpn AF, before `exit`):

```
 address-family l2vpn evpn
  neighbor ${PEER_ADDR} activate
  advertise-all-vni
  advertise-svi-ip
 exit-address-family
```

Add to VRF red ipv4 unicast AF (after `redistribute connected`):

```
${L2EVPN_VRF_NETWORK}
```

Where `L2EVPN_VRF_NETWORK`:
- PE1/PE2/PE3: `  network 192.168.10.0/24`
- RemotePE: empty string

### 3. Modified: `tor/frr.conf`

Add l2vpn evpn AF to global BGP:

```
 address-family l2vpn evpn
  neighbor CLIENTS activate
  neighbor CLIENTS route-reflector-client
  advertise-all-vni
  advertise-svi-ip
 exit-address-family
```

### 4. Modified: `generate.sh`

Add `generate_l2evpn()` function that:
- Takes node_dir as argument
- Runs envsubst on `l2evpn-setup.sh.tpl` and appends to `${node_dir}/setup.sh`

Add new variables per PE:
- `VTEP_V4`, `BRIDGE_PORT_IP`, `BRIDGE_MAC`
- `L2EVPN_VRF_NETWORK` (set for PE1/2/3, empty for RemotePE)

Call `generate_l2evpn` for PE1, PE2, PE3 only (not RemotePE).

Add `L2EVPN_VRF_NETWORK` to envsubst variable list for `pe-frr.conf.tpl`.

### 5. Modified: `setup.sh`

After convergence wait, add seed pings:

```bash
echo "Seeding L2 EVPN neighbor tables..."
sleep 5
for pe in pe1 pe2 pe3; do
    for target in 192.168.10.1 192.168.10.2 192.168.10.3; do
        docker exec clab-evpnsrv6-${pe} ping -c 1 -W 1 -I br10 ${target} &>/dev/null &
    done
done
wait
echo "Neighbor tables seeded."
```

### 6. Regenerated configs

Run `generate.sh` to regenerate pe1/, pe2/, pe3/, remotepe/ with new L2 EVPN additions.

## Verification Steps

1. Deploy: `./setup.sh`
2. Check BGP EVPN on TOR: `docker exec clab-evpnsrv6-tor vtysh -c "show bgp l2vpn evpn summary"`
3. Check EVPN routes on PE1: `docker exec clab-evpnsrv6-pe1 vtysh -c "show bgp l2vpn evpn"`
4. Check VNI: `docker exec clab-evpnsrv6-pe1 vtysh -c "show evpn vni"`
5. Ping PE1→PE2 (L2): `docker exec clab-evpnsrv6-pe1 ping -c 3 -I br10 192.168.10.2`
6. Ping PE1→PE3 (L2): `docker exec clab-evpnsrv6-pe1 ping -c 3 -I br10 192.168.10.3`
7. Check neighbor table: `docker exec clab-evpnsrv6-pe1 ip neigh show dev br10`
8. Ping PE1→RemotePE VRF loopback: `docker exec clab-evpnsrv6-pe1 ip vrf exec red ping -c 3 -I 192.168.10.1 10.10.20.1`
9. Verify SRv6 L3VPN still works: `docker exec clab-evpnsrv6-pe1 ip vrf exec red ping 10.10.20.1`
