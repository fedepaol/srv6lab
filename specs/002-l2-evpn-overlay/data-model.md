# Data Model: L2 EVPN VXLAN Overlay

## Network Entities

### Bridge (br10)
- **Type**: Linux bridge interface
- **Scope**: PE1, PE2, PE3 only
- **VRF**: red (table 1100)
- **MAC**: Static per PE (aa:bb:cc:00:00:0X)
- **IP**: 192.168.10.X/24 (X = PE number)
- **Relationship**: Master of vni110. Member of VRF red.

### VXLAN Interface (vni110)
- **Type**: VXLAN tunnel interface
- **VNI**: 110
- **Local VTEP**: PE IPv4 loopback (10.0.0.X)
- **Port**: UDP 4789
- **Flags**: nolearning, neigh_suppress on, learning off, addrgenmode none
- **Relationship**: Slave of br10.

### L2 Domain (VNI 110)
- **Subnet**: 192.168.10.0/24
- **Members**: PE1 (.1), PE2 (.2), PE3 (.3)
- **Forwarding**: VXLAN encapsulation between PEs
- **Control plane**: BGP EVPN Type-2 (MAC/IP), Type-3 (BUM)

## BGP EVPN Route Types

| Type | Purpose | Generated by |
|------|---------|--------------|
| Type-2 (MAC/IP) | MAC + IP binding for each bridge port | PEs after traffic triggers learning |
| Type-3 (Inclusive Multicast) | BUM traffic replication tree per VNI | PEs automatically when VNI configured |

## Routing Relationships

```
PE bridge port (192.168.10.X)
  └── VRF red (L3)
       ├── SRv6 VPN → RemotePE VRF red (10.10.20.1)
       └── BGP network statement → advertises 192.168.10.0/24 to RemotePE

PE bridge (br10)
  └── VXLAN vni110 (L2)
       └── BGP EVPN (l2vpn evpn AF) → TOR RR → other PEs
```
