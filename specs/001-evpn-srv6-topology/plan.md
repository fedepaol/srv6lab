# Implementation Plan: EVPN SRv6 Containerlab Topology

**Branch**: `002-evpn-srv6-topology` | **Date**: 2026-04-23 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/001-evpn-srv6-topology/spec.md`

## Summary

Containerlab topology with 5 FRR nodes (PE1, PE2, PE3, TOR, RemotePE) connected via a linux bridge and point-to-point link. ISIS underlay, SRv6 overlay with iBGP full mesh, VRF "red" on each PE with unique loopback addresses. Following srv6labpoc structure: per-node directories with FRR config + setup.sh, global setup.sh for teardown/deploy.

**Structure Decision**: Template-based approach. PE1/PE2/PE3/RemotePE share identical structure (ISIS + BGP + SRv6 + VRF) differing only in addresses. Templates in `templates/` use `${VARIABLE}` placeholders; `generate.sh` defines per-node variables and runs `envsubst` to produce final configs. TOR is hand-written (unique ISIS-only config). Global setup.sh orchestrates containerlab deploy and per-node setup execution.

## Design Decisions

### Addressing Plan

See [data-model.md](data-model.md) for complete tables. Key design:

- **Underlay loopbacks**: 10.0.0.{1,2,3,10,20}/32 + fc00:0:{1,2,3,10,20}::1/128
- **Bridge segment**: 10.100.0.0/24 + fc00:100::/64 (PE1/PE2/PE3/TOR)
- **TOR↔RemotePE**: 10.200.0.0/31 + fc00:200::/127
- **SRv6 locators**: fd00:{1,2,3,20}::/48 with uSID
- **VRF loopbacks**: 10.10.{1,2,3,20}.1/32 + fc00:10:{1,2,3,20}::1/128

### ISIS Configuration

- Area 49.0001, level-1, ipv6-unicast topology
- Bridge interfaces: broadcast mode (default — multi-access L2 segment)
- TOR↔RemotePE: point-to-point mode
- Segment routing enabled on all nodes

### BGP Configuration

- iBGP full mesh AS 65500 among PE1/PE2/PE3/RemotePE (6 sessions)
- TOR: no BGP (pure transit)
- Address-family: ipv6 vpn with SRv6 locator MAIN
- VRF "red": sid vpn per-vrf export auto, RD <router-id>:2, RT 65500:2

### Containerlab Topology

- Topology name: `evpnsrv6`
- Bridge node: `kind: bridge` (no image)
- FRR nodes: `kind: linux`, image `quay.io/frrouting/frr:10.6.0`
- Binds: `<node>/:/etc/frr/` + `<node>/setup.sh:/setup.sh`

### Node Setup Scripts

PE-type nodes (PE1/PE2/PE3/RemotePE) via `templates/pe-setup.sh.tpl`:
1. Enable IPv4/IPv6 forwarding + SRv6 sysctls + vrf strict_mode
2. Create dummy `sr0` interface (SRv6)
3. Add underlay loopback addresses to `lo` (${LOOPBACK_V4}, ${LOOPBACK_V6}, ${SRV6_LOOPBACK})
4. Add link addresses on ${ISIS_IFACE} (${LINK_V4}, ${LINK_V6})
5. Create VRF "red" (table 1100)
6. Create dummy `lored` in VRF with unique addresses (${VRF_LO_V4}, ${VRF_LO_V6})

TOR setup.sh (hand-written, static):
1. Enable IPv4/IPv6 forwarding + SRv6 sysctls
2. Add underlay loopback addresses to `lo`
3. Add link addresses on eth1 (bridge) and eth2 (to RemotePE)

generate.sh:
1. Define per-node variable arrays (PE1, PE2, PE3, RemotePE)
2. For each PE-type node: export variables, run `envsubst < template > output`
3. Copy shared daemons and vtysh.conf to all node directories (including TOR)

Global setup.sh:
1. `sudo clab destroy --topo topology.clab.yaml` (ignore errors)
2. `sudo clab deploy --topo topology.clab.yaml`
3. `docker exec clab-evpnsrv6-<node> /setup.sh` for each node
